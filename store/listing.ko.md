# Chrome 웹 스토어 한국어 설명문

대시보드의 **스토어 등록정보 → 언어 추가 → 한국어**에 붙여넣는 텍스트.
영어판(`listing.md`)과 같은 원칙을 지킨다: **"준수를 보장한다"는 표현을 쓰지 않는다.**
접근성은 장애인차별금지법과 얽힌 규제 영역이라, 과장은 환불 요청과 별점 1점보다
훨씬 큰 책임으로 돌아온다. 자동 검사가 못 잡는 것을 설명문에서 먼저 말한다.

이름과 짧은 설명은 `_locales/ko/messages.json`에서 매니페스트가 가져가므로
그쪽을 바꾸면 여기도 같이 바꾼다.

## 이름 (45자 제한)

```
A11yScope — 웹 접근성·WCAG 검사기
```
26자.

## 짧은 설명 (132자 제한)

```
어떤 페이지든 클릭 한 번으로 WCAG 2.2 AA 접근성 문제를 찾습니다. 명도 대비, 레이블, 제목, ARIA. 계정 불필요.
```
72자.

## 상세 설명

스토어는 줄바꿈을 그대로 보여주므로 **문단은 한 줄**로 둔다 (2026-10-08, 제출하다 발견).

```
A11yScope는 지금 보고 있는 페이지를 WCAG 2.2 Level AA 중 자동으로 검사할 수 있는 항목에 대조하고, 무엇을 고쳐야 하는지 알려 줍니다. 한국 웹 콘텐츠 접근성 지침 (KWCAG 2.2)은 WCAG의 성공 기준을 거의 그대로 따르므로, 결과는 그대로 KWCAG 항목에 대응합니다.

검사 버튼을 누르면 결과가 사이드 패널에 검사 항목별로 묶여 나타나고, 각 항목에는 근거가 되는 성공 기준 번호가 붙습니다. 결과 하나를 선택하면 해당 요소가 페이지 위에서 강조 표시되어, 문제가 어디 있는지 찾아 헤맬 일이 없습니다.

패널, 검사 항목 설명, 결과 메시지가 모두 한국어로 나옵니다. Chrome이 한국어로 설정되어 있으면 자동으로 전환됩니다.

검사 항목 — 31가지

텍스트 대체
· 대체 텍스트가 없는 이미지, 파일 이름만 반복하는 대체 텍스트
· 레이블이 없는 폼 컨트롤 (placeholder는 레이블이 아닙니다)
· 접근 가능한 이름이 없는 버튼과 링크
· title이 없는 프레임, 이름 없는 SVG 그래픽
· 목적지를 설명하지 않는 링크 텍스트

명도 대비
· 4.5:1에 못 미치는 텍스트 — 측정된 비율과 두 색상을 함께 표시
· 큰 텍스트와 굵은 텍스트의 완화 기준을 정확히 적용
· 반투명 배경은 상위 요소를 모두 합성해 실제 색으로 계산

구조
· 페이지 언어가 없거나 잘못됨
· 페이지 제목이 없거나 임시 제목
· 건너뛴 제목 수준, 빈 제목, 없거나 중복된 h1
· main 랜드마크 없음, 반복 내비게이션을 건너뛸 방법 없음
· 머리글 셀이 없는 데이터 표, 잘못된 목록 구조
· ARIA나 레이블이 실제로 참조하는 중복 id

키보드·포인터·ARIA
· 뷰포트 메타 태그로 막아 둔 확대
· Tab 순서를 뒤섞는 양수 tabindex
· 스크린 리더에는 숨겼지만 포커스는 되는 요소
· 서로 중첩된 대화형 컨트롤
· WCAG 2.2에서 새로 도입된 24×24 최소 크기에 못 미치는 포인터 대상
· 자동 재생 오디오, 자막 트랙이 없는 동영상
· 철자가 틀린 ARIA role, 필수 상태 속성이 빠진 role
· 개인정보 입력란에 빠진 autocomplete
· 대체 표시 없이 제거한 포커스 표시

한국 사이트에 맞춘 보정

실제 한국 사이트(네이버, 11번가, 다나와, 토스, 카카오 등)를 돌려 보며 오탐을 줄였습니다. 스크린 리더 전용으로 숨긴 텍스트의 대비를 재지 않고, "토스"처럼 짧은 한글 제목을 문제 삼지 않으며, 숨겨 둔 메뉴를 포인터 대상으로 세지 않습니다.

하지 않는 것

자동 검사는 접근성 장벽의 약 3분의 1을 찾아냅니다. 문제가 없다는 결과는 좋은 신호일 뿐, 준수 증명서가 아닙니다. 대체 텍스트가 정확한지, 스크린 리더로 읽었을 때 페이지가 말이 되는지, 키보드 사용자가 작업을 끝낼 수 있는지 — 어떤 도구도 답할 수 없고, 이 도구도 그런 척하지 않습니다. 장애인차별금지법이나 KWCAG 준수 여부는 사람이 하는 전문 평가로만 확인할 수 있습니다.

자동으로 판정할 수 없는 항목은 통과나 실패가 아니라 "검토 필요"로 표시합니다. 각각은 무시해도 되는 오탐이 아니라 사람이 답해야 하는 실제 질문입니다.

개인정보

검사는 전부 브라우저 안에서 실행됩니다. 아무것도 업로드하지 않으며, 계정도 로그인도 사용 분석도 없습니다. activeTab 권한을 쓰기 때문에 사용자가 검사 버튼을 누른 페이지만 읽을 수 있습니다. 소스 코드는 공개되어 있어 직접 확인할 수 있습니다.

이런 분께

접근성 문제를 찾아 고쳐야 하는 프런트엔드 개발자, 디자이너, QA 엔지니어, 에이전시. 공공기관 웹 접근성 인증을 준비하는 팀, 그리고 2025년 6월 28일부터 시행된 유럽 접근성법(EAA)에 대응해야 하는 팀.
```

## 대시보드 입력 순서 (사용자가 할 일)

1. https://chrome.google.com/webstore/devconsole → A11yScope → **패키지** 탭 → `dist/a11yscope-0.3.0.zip` 업로드
2. **스토어 등록정보** 탭 → 상단 언어 선택에서 **언어 추가 → 한국어**
3. 위 상세 설명을 붙여넣기. 이름과 짧은 설명은 매니페스트에서 자동으로 채워진다
4. 스크린샷은 영어판 것을 그대로 두어도 된다 (한국어 패널 캡처는 다음 판에서)
5. **검토를 위해 제출**

심사 결과는 `perceivablehq@gmail.com`으로 온다.
